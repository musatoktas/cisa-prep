# Week 3: Acquisition, Development and Implementation (12%), then Domain 4 begins

Domain 3 is the smallest domain, so it gets three and a half days. The rest of the week starts Domain 4, the largest.

| Day | Topic | Read | Practise |
|---|---|---|---|
| Mon | Project governance and management, business case, feasibility study, benefits realisation | CRM Domain 3, Part A | 40 Qs on projects and business cases |
| Tue | System development methodologies (waterfall, agile, DevOps), requirements, control design in applications (input, processing, output controls) | CRM Domain 3, Part A | 40 Qs on SDLC and application controls |
| Wed | Testing (unit, integration, system, UAT, regression), configuration and release management, data conversion and migration, cutover approaches | CRM Domain 3, Part B | 45 Qs on testing and migration |

| Sun | Review | Your wrong-answer log | 50 mixed Qs from Domains 1 to 3 |

## Concepts you must be able to explain without notes

- When the auditor should be involved in a project (early, as an adviser on controls, without designing or approving them)
- Why user acceptance testing is signed off by the business, not by IT
- Parallel run vs pilot vs phased vs direct cutover, and the risk of each
- Control totals, hash totals, check digits, edit and validation checks
- Why developers should not migrate their own code to production, and what replaces that control in DevOps
- What a post-implementation review measures (benefits realised, controls working, lessons learned)
